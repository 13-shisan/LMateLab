# LMateLab 107 杯前端完整形态预览设计

## 1. 文档状态

本设计于 `2026-08-10` 经用户逐段确认，覆盖信息架构、新建计算、工作流与结果、VASP 数据库、角色权限、复用边界、数据流、独立预览部署和验收门禁。

本文件是 `docs/107cup/implementation-plan.md` 的专项设计，不是第二份总路线。实施顺序、阶段状态和 107 运行证据仍以总实施方案为准。

本设计只授权后续编写实施计划，不表示前端、后端、Slurm 或 VASP 功能已经实现、构建或部署。

## 2. 目标

先交付一套可继续演进的 React 最终形态前端，使用户能够看到 107 杯项目最终包含的核心页面和操作路径，再按既定路线逐项接入真实数据库、Slurm 和 VASP 能力。

前端必须始终围绕以下主线：

```text
结构
  -> relax
  -> SCF
  -> BAND
  -> DOS
  -> 图表、数据库与证据包
```

第一批真实输入范围固定为：

- 内置单层 MoS2 模板。
- Operator 上传一个小型 POSCAR 或 CIF 文件。
- 上传文件最大 `1 MiB`、最多 `200` 个原子，只接受文本结构文件，不接受压缩包或目录。
- 合法结构先保存为可追溯草稿；确认提交前不得创建 Slurm Job ID。

最终需要完整的 VASP 数据库浏览能力，但第一阶段真实数据源只包含 107 竞赛工作流产生并通过验收的记录。

## 3. 非目标

本设计不加入以下功能：

- Agent、聊天、RAG、Ollama 或知识库。
- 机器学习、主动学习或跨服务器迁移。
- QE、EPW、Gaussian、DeepMD、LASP 或 CP2K 工作流。
- 任意模板上传、任意命令、任意 Slurm 脚本或任意路径浏览。
- 将原 4090 LMateLab 的生产数据库、运行数据、上传文件、日志或密钥复制到 107。
- 恢复原项目中与竞赛主线无关的实验记录、论文、报告或服务器监控页面。
- 在前端预览阶段伪造提交、取消、数据库写入或 VASP 成功。

## 4. 已确认的信息架构

107 专用应用入口继续使用 `App107Cup.jsx`，认证后只显示以下五个核心入口：

| 页面 | 路由 | 目的 |
|---|---|---|
| 工作台 | `/dashboard` | 汇总工作流状态、近期计算和 Slurm 资源摘要 |
| 新建计算 | `/dashboard/calculations/new` | 选择结构、预览、确认四步流程、参数与资源 |
| 工作流 | `/dashboard/workflows` | 检索工作流并查看步骤、Job ID、日志、取消和重试状态 |
| 结果 | `/dashboard/results` | 浏览已完成或失败结果；详情使用 `/dashboard/results/:workflowId` |
| VASP 数据库 | `/dashboard/database/vasp` | 用元素周期表、搜索和表格检索结构及电子性质 |

所有路由必须支持浏览器直接刷新。未知受保护路由回到工作台；未登录用户回到登录页。

### 4.1 工作台

工作台是操作型总览，不是营销首页。它包括：

- 工作流总数、运行中、近期完成和需要处理的数量。
- 最近工作流表格，显示材料、来源、当前步骤、状态和最新 Job ID。
- 当前四步时间线，明确区分已验收、运行中、等待和失败。
- 新建计算入口。
- Slurm 资源摘要只展示与竞赛相关的最少信息，不暴露同账号下其他作业内容。

### 4.2 新建计算

采用单页分步工作区：

1. 选择结构。
2. 确认计算步骤。
3. 确认参数。
4. 确认资源与提交。

结构页左侧选择内置 MoS2 或上传文件，中间使用现有 3Dmol 组件显示结构和晶格摘要，右侧持续显示固定的 `relax -> SCF -> BAND -> DOS` 依赖链。

第一版不能删除、重排或插入步骤。BAND 和 DOS 都依赖已验收 SCF，而不是互相依赖。

预览模式允许查看所有控制和切换步骤，但上传、保存、提交等写操作必须明确禁用并说明“预览环境不会写入或提交”。它们不能返回模拟成功提示。

### 4.3 工作流与结果

工作流详情和结果详情共享同一身份信息：工作流 ID、创建人、模板版本、输入结构哈希、发布提交和演示/真实数据标记。

左侧时间线显示每一步的：

- 状态与阶段验收结论。
- 独立 Slurm Job ID。
- attempt 编号和目录标识。
- 原始 Slurm state、ExitCode、reason 和时间戳。
- VASP 正常结束、收敛和文件完整性摘要。

右侧结果区域包含：

- 最终结构。
- BAND 标签页。
- DOS 标签页。
- 关键电子性质。
- 绘图数据、结构文件和证据包下载。

只有对应步骤和解析合同通过时才显示成功结果。缺文件、不收敛或解析失败时显示失败证据，不能显示空白成功图。

### 4.4 周期表驱动的 VASP 数据库

VASP 数据库保留原项目的完整元素周期表，并将它作为核心筛选入口，而不是装饰组件。

周期表必须支持：

- 数据库中存在的元素高亮。
- 单元素和多元素选择。
- “至少含有所选元素”。
- “只含所选元素”。
- 清空选择。
- 已选元素可见且可单独移除。

周期表下方使用紧凑表格，至少显示材料、来源、工作流、状态、带隙、总能、完成时间和详情入口。点击记录后，右侧显示结构、组成、关键性质、最后 Job ID、BAND/DOS 可用性和证据包入口。

页面按完整数据库规模设计，但首个真实接口只查询 107 竞赛数据库。后续扩大数据量时保持同一周期表、筛选、分页和详情合同。

## 5. 复用优先原则

后续实现不得因为竞赛入口被裁剪而重写原项目已有的科学展示能力。优先级固定为：

```text
直接 import 复用
  -> 提取为受控公共组件
  -> 通过薄适配层保持原合同
  -> 仅在强耦合且无法安全分离时新增实现
```

### 5.1 直接复用

- `frontend/src/pages/db/vasp-detail/VaspStructureViewer.jsx`：3Dmol 初始化、元素颜色、晶胞、坐标轴、缩放和错误状态。
- `frontend/src/pages/db/vasp-detail/VaspCrystalDetails.jsx`：晶格与结构详情。
- `frontend/src/pages/db/vasp-detail/VaspElectronicProperties.jsx`：BAND/DOS 标签页、按需加载、缓存和数据导出。
- `frontend/src/pages/db/vasp-detail/VaspTaskSummary.jsx`：结构摘要、元素图例、性质和导出菜单。
- `frontend/src/utils/elementColors.js`、`elementCategory.js`、格式化和鉴权请求工具。
- `backend/services/vasp_task_detail.py`：白名单化的任务详情数据合同。
- 现有结构、BAND、DOS 和导出解析服务。
- 已锁定的 `3dmol`、Chart.js/Recharts 和 Lucide 依赖。

### 5.2 提取后复用

`PersonalVaspDatabase.jsx` 当前把 118 元素数据、周期表渲染、旧数据库选择、后台扫描、上传和自定义库写入放在同一页面。实施时提取以下公共单元：

- `PeriodicTableFilter`：受控组件，只接收存在元素、已选元素、匹配模式和回调。
- `periodicTableElements`：118 元素位置和名称数据。
- `VaspRecordTable`：只负责响应式表格、格式化、分页和详情链接。

原 `PersonalVaspDatabase` 继续通过兼容包装器使用这些单元，保持 4090 原项目行为不变。竞赛页面不 import 旧库上传、收藏或删除逻辑。

### 5.3 不直接复用

- 不挂载完整 `backend/routers/vasp_db.py` router，因为它同时开放旧库扫描、上传、自定义数据库和写操作。
- 不直接挂载完整 `PersonalVaspDatabase.jsx`，因为它依赖旧数据库范围和写接口。
- 不直接复用带收藏和删除动作的旧 `VaspDataTable` 外层；只复用提取后的只读表格核心。
- 不直接复用 `VaspTaskDetail.jsx` 的旧 `DbLayout` 路由编排；复用它已经拆出的科学子组件。

## 6. 前端架构

竞赛前端使用同一套页面和两个数据提供器：

```text
React 页面
  -> competitionDataProvider
       -> demoCompetitionDataProvider
       -> apiCompetitionDataProvider
```

### 6.1 演示数据提供器

独立前端预览固定使用 demo 提供器：

- 数据来自版本控制内的最小 MoS2 成功、运行中和人为失败 fixtures。
- 全局和页面局部都显示“演示数据”。
- 查询、筛选、标签页、3D 旋转和步骤切换可以工作。
- fixture 的 BAND/DOS 图、数据下载和证据样例必须标为演示内容。
- 所有 mutation 方法抛出 `PreviewReadOnlyError`，同时 UI 层禁用对应控件。
- 不发送上传、草稿保存、提交、取消、重试或数据库写请求。

### 6.2 真实 API 提供器

正式模式使用真实 API：

- Dashboard 和工作流使用 `/api/competition/...` 领域接口。
- 结构、BAND、DOS 和数据库读取由竞赛专用薄 router 提供。
- 对现有科学组件保持兼容的 GET 路径和响应形状。
- 所有写请求携带应用身份，并由后端再次检查角色和资源归属。

数据模式由构建时配置固定，运行时用户不能切换 demo/live。预览发布必须固定为 demo，正式发布必须固定为 live。

## 7. 后端边界与数据流

`backend/competition_runtime.py` 只新增明确列出的竞赛 router，不恢复完整业务 router 集合。

领域接口使用：

- `/api/competition/dashboard`
- `/api/competition/workflows`
- `/api/competition/workflows/{workflow_id}`
- `/api/competition/results/{workflow_id}`

竞赛专用 VASP 薄 router 只允许所需 GET 能力：

- 元素集合与记录列表。
- 任务详情。
- 结构导出。
- BAND/DOS 图片与数据导出。

它可以保持现有 `/api/db/vasp/...` 的只读路径形状以复用组件，但不得暴露原 router 的上传、扫描、收藏、自定义库创建、移除或删除接口。

真实数据流固定为：

```text
结构输入
  -> 格式、大小、原子数、元素顺序和路径校验
  -> 文件 SHA-256 与草稿记录
  -> Operator 确认
  -> 固定 Slurm 适配器
  -> 独立 relax/SCF/BAND/DOS attempts
  -> 阶段验收
  -> 现有解析服务
  -> 竞赛数据库、图表和证据包
```

草稿校验失败可以记录事件，但不能产生 Job ID 或执行 attempt。Slurm、VASP 和解析任一门禁失败都阻止后续步骤显示为成功。

## 8. 角色与权限

### 8.1 Operator

Operator 可以：

- 创建和编辑自己的草稿。
- 上传一个受限 POSCAR/CIF。
- 提交固定工作流。
- 查看日志。
- 取消或重试由 LMateLab 创建且归属于当前工作流的作业。
- 下载结果和证据包。

取消前必须同时核对 JobName、WorkDir、Slurm comment 和数据库 ledger。不能操作同一 107 Unix 账号下的其他作业。

### 8.2 Demo Viewer

Viewer 可以只读查看：

- 工作台。
- 工作流状态和脱敏日志。
- 最终结构、BAND、DOS 和关键性质。
- VASP 数据库。
- 不含敏感信息的结果与证据包。

Viewer 不能上传、创建草稿、提交、取消、重试或修改数据库。后端返回 `403`，不能仅由前端隐藏按钮。

## 9. 错误与状态设计

所有主要区域必须实现稳定的显式状态：

| 状态 | 行为 |
|---|---|
| loading | 保持稳定尺寸，不因加载文字改变布局 |
| empty | 说明当前筛选无记录，不补演示成功数据 |
| demo | 持续标识演示数据，禁用写操作 |
| stale | 显示最后可信状态和更新时间，不改写为成功或失败 |
| forbidden | 显示权限不足，后端返回 403 |
| failed | 保留失败步骤、Job ID、退出状态和日志 |
| parse-error | 显示解析失败证据，不显示成功 BAND/DOS |
| render-error | 只影响 3D 或图表区域，其他信息继续可用 |

3Dmol、BAND、DOS 和下载错误不得造成整页崩溃。失败和成功数据使用不同状态合同，不能用空数组或空图片代表成功。

## 10. 响应式与交互要求

- 桌面使用紧凑侧栏和高信息密度内容区。
- `1024px` 窄屏允许减少并排列数，但不隐藏关键状态和 Job ID。
- `390px` 移动端改为单列，表格在自身区域横向滚动，不能扩宽整个文档。
- 周期表在小屏内横向滚动，不能压缩到无法辨认。
- 固定格式组件使用稳定高度、宽度、网格轨道或 `aspect-ratio`。
- 所有文本可换行，不得重叠、遮挡或溢出按钮。
- 使用 Lucide 图标和现有设计系统；不新增另一套图标或图表库。
- 3D 结构必须可旋转、缩放和复位，并为渲染失败提供可见状态。

## 11. 独立 107 预览部署

前端预览不替换稳定服务，部署流程固定为：

1. 从功能分支固定提交创建不晋升的预览发布。
2. 通过 107 Slurm 计算节点安装依赖、运行测试和构建 Vite。
3. 写入独立 `previews/<commit>` 发布目录和 SHA-256 manifest。
4. 使用独立认证数据库、业务数据库、runtime 目录、状态文件和未占用端口。
5. 提交独立 Slurm 预览服务 Job。
6. 通过 Windows 隧道或 4090 只读网络转发访问；4090不保存业务数据。
7. 预览验收后只停止预览 Job，不切换 `current`，不停止稳定服务。

部署前后必须只读记录稳定 `current`、正式数据库哈希/完整性、稳定服务 Job 元数据和健康检查。预览脚本不得修改这些目标。

具体端口在部署时通过只读监听检查选择并记录，不在设计文档中预占未验证端口。

## 12. 验收门禁

### 12.1 自动测试

- 路由和导航测试覆盖五个核心入口及刷新行为。
- demo 提供器测试证明所有 mutation 失败关闭且不发网络写请求。
- API 提供器测试覆盖请求路径、角色错误和数据状态映射。
- 周期表测试覆盖高亮、多选、两种匹配模式和清空。
- 结构组件测试覆盖空结构、3Dmol 载入失败和清理。
- BAND/DOS 测试覆盖按需加载、缓存、不可用和解析失败。
- 表格测试覆盖分页、筛选、移动布局和只读动作。
- 运行现有前端测试、针对性 ESLint、Vite production build 和 `git diff --check`。

### 12.2 浏览器验收

针对 `1440x900`、`1024x768` 和 `390x844`：

- 五个入口均可打开和刷新。
- 结构来源、步骤、周期表、筛选、标签页和 3D 旋转可交互。
- 页面无重叠、裁切、异常横向扩宽或文字溢出。
- Canvas 非空且结构位于可见范围。
- 控制台无相关 error 或 warning。
- 演示数据标识始终可见。
- 写操作禁用且不会产生成功提示。

### 12.3 107 预览验收

- 构建和服务均有真实 Slurm Job ID、节点、提交和日志。
- 预览 release manifest 在作业内复核通过。
- 健康检查返回预览 Job、节点和提交。
- 服务 Job 结束后预览端口不可达。
- 稳定 `current`、正式数据库和稳定服务 Job 在预览前后保持不变。

## 13. 完成定义

本前端预览批次只有在以下条件全部满足后才能记录为完成：

- 已确认的五页前端形态以真实 React 组件实现。
- 原项目可复用组件按本设计复用或提取，没有复制第二套科学展示逻辑。
- demo/live 数据边界清晰，预览环境没有写接口成功路径。
- 本地针对性测试和构建通过只能记录为本地证据。
- 107 Slurm 构建、独立预览服务和浏览器验收均产生可追溯证据。
- 预览未影响稳定入口、正式数据库或稳定服务。

真实工作流模型、真实 Slurm 控制、真实 VASP 四步闭环和完整竞赛数据库仍分别遵守总实施方案的阶段 5 至 8 门禁；前端预览不能替代这些验收。
